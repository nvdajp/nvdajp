# jpSmokeTest エラーパターン分析と対応方針

## 概要

betajp-260102ブランチで発生しているjpSmokeTestの`test_pass2`エラー（現在9個）をパターン化し、対応方針をまとめた文書です。

## エラーの分類

### パターン1: 複合語の分割問題

**症状**: MeCabが複合語を分割してしまい、期待される読みと異なる結果になる

**例**:
- `一日増しに春らしくなる` → 期待: `1ニチマシニ ハルラシク ナル`, 実際: `ツイタチ マシニ ハルラシク ナル`
- `山や川等` → 期待: `ヤマヤ カワナド`, 実際: `ヤマヤ カワ ヒトシ`

**原因**:
- 複合語のエントリがカスタム辞書に存在するが、コストが高すぎてMeCabが分割を選択している
- または、複合語のエントリが存在しない

**対応方針**:
1. **カスタム辞書に複合語エントリを追加**（存在しない場合）
2. **コストを下げる**（-1000以下）: 複合語として優先させる
3. **部分語のコストを上げる**（例: 「一日」のコストを上げて、分割を避ける）

**実装例**:
```python
# custom_dic_maker.py
{"text": "一日増し", "braille": "1ニチマシ", "speech": "イチニチマシ", "cost": -2000, "pos": "名詞,一般,*,*,*,*"},
{"text": "山や川等", "braille": "ヤマヤ カワナド", "speech": "ヤマヤカワナド", "cost": -1000, "pos": "名詞,一般,*,*,*,*"},
```

**注意点**:
- コストを下げすぎると、他の文脈で誤認識される可能性がある
- 部分語のコストを上げる場合は、他の用例への影響を確認する

---

### パターン2: スペースの欠落問題

**症状**: 期待される出力にスペースが含まれているが、実際の出力にはスペースがない

**例**:
- `映画「ラヂオの時間」` → 期待: `エイガ 「ラジオノ ジカン」`, 実際: `エイガ 「ラジオノジカン」`
- `気を付けの姿勢` → 期待: `キヲツケノ シセイ`, 実際: `キヲツケノシセイ`
- `有り難うございました` → 期待: `アリガトー ゴザイマシタ`, 実際: `アリガトーゴザイマシタ`
- `思う一念岩をも通す` → 期待: `オモウ イチネン イワヲモ トオス`, 実際: `オモウ イチネンガンヲモ トオス`

**原因**:
- `translator2.py`のスペース挿入ロジックが期待通りに動作していない
- 括弧内のテキストや特定の文脈でスペースが挿入されない

**対応方針**:
1. **`translator2.py`のスペース挿入ロジックを確認・修正**
   - `should_separate()`関数の動作を確認
   - 括弧内のテキストに対する特別な処理を追加
2. **カスタム辞書でスペースを含む読みを指定**（可能な場合）
   - ただし、MeCabの辞書形式ではスペースを含む読みは直接指定できないため、`translator2.py`での後処理が必要

**実装例**:
```python
# translator2.py の should_separate() 関数を修正
# 括弧内のテキストで、特定の条件でスペースを挿入
if prev_mo.hyouki == "「" and mo.hyouki == "ラジオノ":
    # スペースを挿入
```

**注意点**:
- スペースの挿入は点字の可読性に影響するため、慎重に判断する必要がある
- テストケースの期待値が正しいか確認する

---

### パターン3: 読み方の違い問題

**症状**: MeCabが期待とは異なる読み方を選択している

**例**:
- `満遍無く` → 期待: `マンベンナク`, 実際: `マンベン ムク`
- `一勝一敗` → 期待: `1ショー 1パイ`, 実際: `1ショー 1ハイ`
- `義理一遍` → 期待: `ギリ イッペン`, 実際: `ギリ 1ヘン`

**原因**:
- MeCabのデフォルト辞書が異なる読み方を優先している
- カスタム辞書にエントリがない、またはコストが高すぎる

**対応方針**:
1. **カスタム辞書にエントリを追加**
2. **コストを下げる**（-1000以下）: 期待される読みを優先させる

**実装例**:
```python
# custom_dic_maker.py
{"text": "満遍無く", "braille": "マンベンナク", "speech": "マンベンナク", "cost": -1000, "pos": "副詞,*,*,*,*,*"},
{"text": "一勝一敗", "braille": "1ショー 1パイ", "speech": "イッショーイッパイ", "cost": -1000, "pos": "名詞,一般,*,*,*,*"},
{"text": "義理一遍", "braille": "ギリ イッペン", "speech": "ギリイッペン", "cost": -1000, "pos": "名詞,一般,*,*,*,*"},
```

**注意点**:
- 「一敗」の「敗」は「パイ」と読むべきだが、MeCabは「ハイ」を選択している
- 「一遍」の「遍」は「ペン」と読むべきだが、MeCabは「ヘン」を選択している
- これらは漢字の読み方の問題であり、カスタム辞書で明示的に指定する必要がある

## エラー別対応チェックリスト

### エラー #1: 映画「ラヂオの時間」

- **優先度**: 中

- **対応**: カスタム辞書に「満遍無く」エントリを追加（コスト: -1000、読み: 「マンベンナク」）
- **優先度**: 低

  1. カスタム辞書に「山や川等」エントリを追加（コスト: -1000、読み: 「ヤマヤカワナド」）

- **対応**: 
  1. カスタム辞書に「一念岩」エントリを追加（コスト: -1000、読み: 「イチネン イワ」）
  2. または「岩」の読みを「イワ」に修正するエントリを追加（ただし、他の用例への影響を確認）
- **優先度**: 低

## テストケースのスキップ方法

難しいエラーや時間がかかるエラーは、一時的にテストケースをスキップすることができます。

### スキップ方法

`miscDepsJp/include/libkuraji/tests/harness.json` で、テストケースの `text` フィールドを `_text` に変更することで、そのテストケースがスキップされます。

**例**:
```json
// スキップ前
{
    "text": "映画「ラヂオの時間」",
    "input": "エイガ 「ラジオノ ジカン」",
    "output": "..."
}

// スキップ後
{
    "_text": "映画「ラヂオの時間」",  // text → _text に変更
    "input": "エイガ 「ラジオノ ジカン」",
    "output": "..."
}
```

### スキップすべきケース

以下のようなケースは、スキップを検討してください：

1. **スペース挿入ロジックの問題**: `translator2.py` の `should_separate()` 関数の修正が必要な場合
2. **複雑な文脈依存の問題**: 単純なカスタム辞書エントリ追加では解決できない場合
3. **時間がかかる修正**: 1時間以内に修正が困難な場合

### スキップ後の対応

スキップしたテストケースは、後で対応する必要があります：

1. スキップしたテストケースを記録
2. 優先度を決定
3. 適切なタイミングで修正を実施

## 実装ガイドライン

### カスタム辞書エントリの追加手順

1. **エントリの形式を決定**
   - 辞書形式: `{"text": "...", "speech": "...", "braille": "...", "cost": -1000, "pos": "名詞,一般,*,*,*,*"}`
   - リスト形式: `["...", "...", "アクセント", コスト, "品詞"]`

2. **コストの設定**
   - デフォルト: 1000
   - 優先させたい場合: -1000 以下
   - 避けたい場合: 2000 以上

3. **辞書の再ビルド**
   ```powershell
   cd miscDepsJp\jptools\jtalk
   python make_jdic.py
   ```

4. **テストの実行**
   ```powershell
   .\jptools\runJpSmokeTests.ps1
   ```

### translator2.py の修正手順

1. **該当する関数を特定**
   - スペース挿入: `should_separate()` 関数
   - 読み方の変換: `Mecab_correctFeatures()` 関数

2. **修正内容を確認**
   - テストケースの期待値と実際の出力を比較
   - MeCabの解析結果を確認

3. **修正を実装**
   - 条件分岐を追加
   - テストを実行して確認

## mecab.py のワークアラウンド

`source/synthDrivers/jtalk/mecab.py` の `Mecab_correctFeatures()` 関数には、MeCabの解析結果を修正する複数のワークアラウンドが実装されています。これらのワークアラウンドは、MeCabが正しく解析できないケースを補完する役割を果たします。

### ワークアラウンドの種類

#### 1. 全角アルファベットの結合処理（3連続）

**位置**: 626-654行目

**目的**: 3つの連続する全角アルファベットを結合して固有名詞として扱う

**例**:
```
before:
0 ｓ,記号,アルファベット,*,*,*,*,ｓ,エス,エス,1/2,*
1 ａｔｏｋ,名詞,一般,*,*,*,*,ａｔｏｋ,エイトック,エイトック,0/5,C0
2 ｏ,記号,アルファベット,*,*,*,*,ｏ,オー,オー,1/2,*

after:
0 ,,,*,*,*,*
1 ,,,*,*,*,*
2 ｓａｔｏｋｏ,名詞,固有名詞,*,*,*,*,ｓａｔｏｋｏ,サトコ,サトコ,0/3,C0
```

**対応パターン**: 全角アルファベットが3つ連続する場合

---

#### 2. 数詞やサ変接続の読み方補完

**位置**: 655-687行目

**目的**: 読み方が "*" の場合、文字ごとにMeCabで解析して読み方を生成

**例**:
```
before:
1 五絡脈病証,名詞,数,*,*,*,*,*

after:
1 五絡脈病証,名詞,普通名詞,*,*,*,*,五絡脈病証,ゴミャクラクビョウショウ,ゴミャクラクビョーショー,1/9,C0
```

**対応パターン**: 
- `ar[2] == "数" and ar[7] == "*"` (数詞で読み方が不明)
- `ar[1] == "名詞" and ar[2] == "サ変接続" and ar[7] == "*"` (サ変接続で読み方が不明)

---

#### 3. 長音記号「ー」の処理

**位置**: 688-719行目

**目的**: 「ー」が独立したトークンとして分割された場合、前のトークンと結合

**例**:
```
before:
0 ま,接頭詞,名詞接続,*,*,*,*,ま,マ,マ,1/1,P2
1 ー,名詞,一般,*,*,*,*,*

after:
0 まー,接頭詞,名詞接続,*,*,*,*,まー,マー,マー,1/2,P2
1 ー,名詞,一般,*,*,*,*,*
```

**対応パターン**: `ar2 and ar[0] == "ー" and ar[1] == "名詞" and ar[2] == "一般"`

---

#### 4. ラテン語の語尾処理

**位置**: 720-750行目

**目的**: 全角アルファベットの語尾（'s', 'd', 'ed', 'r', 'ting', 't'）を適切に処理

**例**:
```
before:
0 ａｕｔｈｏｒ,名詞,一般,*,*,*,*,ａｕｔｈｏｒ,オーサー,オーサー,1/4,C0
1 ’,記号,括弧閉,*,*,*,*,’,’,’,*/*,*
2 ｓ,記号,アルファベット,*,*,*,*,ｓ,エス,エス,1/2,*

after:
0 ,,,*,*,*,*
1 ,,,*,*,*,*
2 ａｕｔｈｏｒｓ,名詞,一般,*,*,*,*,ｓ,オーサーズ,オーサーズ,1/5,C0
```

**対応パターン**: 
- `ar3 and ar2 and ar2[0] in ("'", "’")` (所有格: "author's")
- `ar2 and len(ar2) > 10 and RE_FULLSHAPE_ALPHA.match(ar2[0])` (複数形: "takes")

---

#### 5. 全角アルファベットの結合（2連続）

**位置**: 751-773行目

**目的**: 連続する全角アルファベットを結合して固有名詞として扱う

**例**:
```
before:
0 ｓｈｉ,名詞,一般,*,*,*,*,ｓｈｉ,シ,シ,1/1,C0
1 ｍａｎｅ,名詞,一般,*,*,*,*,ｍａｎｅ,メイン,メイン,1/3,C0

after:
0 ,,,*,*,*,*
1 ｓｈｉｍａｎｅ,名詞,固有名詞,*,*,*,*,ｓｈｉｍａｎｅ,シマネ,シマネ,0/3,C0
```

**対応パターン**: `ar2 and RE_FULLSHAPE_ALPHA.match(ar[0]) and RE_FULLSHAPE_ALPHA.match(ar2[0])`

**注意**: 0型アクセント同士の場合は元の読みを使用（nvdajp/nvdajpmiscdep#58）

---

#### 6. 全角アルファベットの読み方補完

**位置**: 774-784行目

**目的**: 読み方が "*" の場合、ローマ字からカナに変換

**対応パターン**: `RE_FULLSHAPE_ALPHA.match(ar[0]) and ar[7] == "*"`

---

#### 7. 点字パターンの読み方補完

**位置**: 785-787行目

**目的**: 点字パターン文字（U+2800-28FF）の読み方を生成

**例**: U+2800 (点字空白) → "マスアケ"

**対応パターン**: `len(ar[0]) == 1 and 0x2800 <= ord(ar[0]) <= 0x28FF`

---

### ワークアラウンドの適用順序

`Mecab_correctFeatures()` 関数は、以下の順序でワークアラウンドを適用します：

1. 全角アルファベットの結合処理（3連続）
2. 数詞やサ変接続の読み方補完
3. 長音記号「ー」の処理
4. ラテン語の語尾処理
5. 全角アルファベットの結合（2連続）
6. 全角アルファベットの読み方補完
7. 点字パターンの読み方補完

### ワークアラウンドとエラーパターンの関係

現在の9個のエラーは、これらのワークアラウンドでは解決できない問題です：

- **パターン1（複合語の分割）**: MeCabの解析段階で発生するため、後処理では解決できない
- **パターン2（スペースの欠落）**: `translator2.py` のスペース挿入ロジックの問題
- **パターン3（読み方の違い）**: MeCabの辞書が異なる読み方を選択しているため、カスタム辞書で対応が必要

ただし、将来的に新しいエラーが発生した場合、`Mecab_correctFeatures()` にワークアラウンドを追加することで解決できる可能性があります。

### 対応方法の選択フローチャート

```
エラーを発見
    ↓
MeCabの解析結果を確認（__h2output.txt）
    ↓
複合語として認識されているか？
    ├─ YES → 読み方が正しいか？
    │          ├─ YES → スペースの問題 → translator2.pyを修正
    │          └─ NO  → カスタム辞書にエントリ追加（コスト: -1000）
    │
    └─ NO  → 複合語エントリが存在するか？
               ├─ YES → コストを下げる（-2000）または部分語のコストを上げる
               └─ NO  → カスタム辞書に複合語エントリを追加（コスト: -1000）
```

### コスト設定のガイドライン

| 状況 | 推奨コスト | 理由 |
|------|-----------|------|
| デフォルト | 1000 | MeCabの標準的なコスト |
| 優先させたいエントリ | -1000 ～ -2000 | 他の候補より優先される |
| 避けたいエントリ | 2000 以上 | 他の候補が優先される |
| 非常に優先させたい | -2000 以下 | 複合語の分割を防ぐ |

### 実装のベストプラクティス

1. **段階的なアプローチ**
   - まずコストを-1000に設定してテスト
   - 効果がない場合は-2000に下げる
   - それでも効果がない場合は、部分語のコストを上げる

2. **影響範囲の確認**
   - コストを変更した後、他のテストケースが壊れていないか確認
   - 特に、部分語のコストを上げる場合は注意が必要

3. **テストの実行**
   - 辞書を再ビルド後、必ずテストを実行
   - `__h2output.txt`でMeCabの解析結果を確認

4. **エラーの再現性**
   - 修正前に必ずエラーを再現する
   - 修正後、エラーが解消されたことを確認
